製作原則

做每一格之前都要照這些原則。原則有變就改這頁（scripts/make_principles.py）。

一、跟 prompt 有關的，一律由模型決定2026-11-12

  • 任何跟 prompt 有關的都不准用程式：每格的背景描述、每格附哪些參考圖、prompt 文字本身。
  • 可以用程式組 request 去問模型（把地圖、旁白、規則整理好送給 Claude），但內容一定要是模型決定的。
  • 程式不能自己算出背景句子、不能自己挑參考圖、不能拿模型的回答再用規則改寫。
  • 程式只做搬運：把寫好的 prompt 貼進 Flow、附上指定的參考圖、下載、切圖。

為什麼：程式從地圖拼出「背後是西牆」「離相機約 4 公尺」「背景橫跨整個畫面：書桌」，Flow 和人都看不懂，02-08 因此把窗戶畫到 HERO 背後。程式用關鍵字挑參考圖，房間圖刪掉後就什麼地點圖都選不到。

二、背景描述怎麼寫2026-11-12

  • 模型一格一格看那格的地圖（相機位置、視野），用直白的句子寫，像在描述一張照片。
  • 先講鏡頭對著哪面牆或哪個方向，再講那邊有什麼。
  • 東西用彼此的關係定位：窗戶下面的書桌、書桌前面的椅子、靠著左邊牆的床。
  • 最後講不在畫面裡的門窗，和光線從哪裡來。
  • 不寫東南西北（Flow 沒有地圖）、不寫幾公尺（Flow 不會量距離）、不用「前景／中景／背景」「畫面最後面」這種詞。
  • 附兩張牆面圖時，要寫清楚哪面牆在左、哪面在右、角落在畫面哪裡、每面牆看得到哪一段；用圖裡的東西指（「有窗戶和書桌的那張」），不寫「第一張」。

範本：EP1-02-01「鏡頭對著房間最裡面的那面牆。牆的正中間有一扇百葉窗。窗戶下面靠牆放著一張長書桌……房門在鏡頭後面，畫面裡看不到。」

三、每格附哪些參考圖2026-11-12

  • 由模型逐格決定。
  • 入鏡的角色：附那個角色的設定圖。HERO 跟恐龍同框：再附那隻恐龍的比例圖（PAIR2）。
  • 室內場景：只附畫面裡看得到的牆面圖。正對一面牆附 1 張，對著角落附 2 張，鏡頭背後的牆不附。
  • 畫面裡有手機、相機、電擊槍、回家按鈕、生存指南：附道具圖 REF_PROPS。

為什麼牆面圖要分開附：整張附上去，鏡頭背後那面牆的東西（例如窗戶）也會被畫進來。

五、畫完之後，先處理要改 prompt 的2026-11-13

  • 看完圖要改的東西，優先處理要改 prompt 的：prompt 沒寫對、沒寫到，或寫了會畫錯的。
  • 多畫幾張就能解決的先不處理：prompt 已經寫對，只是 Flow 剛好畫歪一兩張。在分鏡表標「不要這張」，挑別張。
  • 判斷方法：打開那格的 prompt 看有沒有寫到。有寫到＝多畫幾張；沒寫到或寫錯＝改 prompt。
  • 改 prompt 的格在分鏡表按「表達不好，要重寫 prompt」寫方向；改之前舊版存進修改紀錄，可以還原。

例：04-22 沒寫 HERO 站在圓環裡、06-06 直接寫甲龍害偽裝破功、13-04 沒寫博士的手要純白 → 改 prompt；12-12 一張畫成光頭、09-02 一張細手細腳 → 不處理。

四、室內場景用四面牆圖2026-11-12

  • 每個室內場景畫一張 2×2 四格圖，四格是四面牆，再切成四張牆面圖上傳。
  • 小房間（HERO 的房間，5 × 4 公尺）：每格站在房間中間看一面牆。
  • 大房間（實驗室，8 × 6 公尺）：每格背靠對面的牆往前看，整面牆從這個角落到那個角落都入鏡。
  • 八方向背景圖（直接當背景照抄）不用：Flow 會整張照搬，景別出不來。
  • 畫出來的圖跟地圖不合時，照圖改地圖（圖會直接附給 Flow）。
  • Flow 裡的名字：房間 ROOM_WINDOW_WALL／ROOM_DOOR_WALL／ROOM_BED_WALL／ROOM_BARE_WALL；實驗室 LAB_MACHINE_WALL／LAB_DOOR_WALL／LAB_CHALKBOARD_WALL／LAB_WORKBENCH_WALL。

六、HERO 跟大恐龍同時入鏡，要多畫遠一級的景2026-11-18

  • HERO 和大恐龍（甲龍、三角龍、鴨嘴龍、矮暴龍、暴龍……）同時入鏡的格，除了原本景別，一定另外多畫一張遠一級（格號加 W）。
  • 遠一級：特寫→近景、中景→中遠景、全景→遠景、遠景→大遠景，依景別表往遠推一級。
  • 原景別允許恐龍不全身入鏡（只露一部分）；遠一級那張讓兩者大小關係看得出來。兩張都畫，剪輯時再挑。

為什麼：尺寸差太多時，原景別常常只能露恐龍一部分，看不出牠有多大；只畫一種，挑圖時沒得比。

七、尺寸參考圖一定要在 prompt 裡說明2026-11-18

  • 附任何尺寸參考（例如比例圖 PAIR2_<恐龍>），prompt 裡必須告訴模型：這張圖畫的是什麼、要怎麼用。不能只附上不說明。
  • 寫法：「One of the attached images is a scale chart showing HERO standing next to ANKY at their true relative size; draw HERO and ANKY at exactly the size ratio shown in that chart.」同框幾隻恐龍就每隻一句，都要附那隻的比例圖。
  • 之後畫圖、重畫一律只用 C 版（上面這句說明比例圖）。A 版（只附圖不說明）、B 版（文字寫幾倍大）都不再用，也不再三版並畫比較。
  • 大小只講這一次：不要再另外寫幾倍、幾成、佔畫面多少。
  • 組畫圖檔的程式要檢查：HERO 和大恐龍同框的格，有沒有附比例圖、有沒有這句說明；缺一個就不送畫。

為什麼：EP2 加長版 2026-11-18 只附了比例圖、prompt 沒說明（A 版），14-01、14-02W 還漏附三角龍和鴨嘴龍的比例圖。11-18 測過（HERO＋大恐龍 30 格，每格 A、B、C 各 4 張）：A 版只被挑中 1 格，理由幾乎都是恐龍太小；B 版 11 格、C 版 18 格。B 版的數字容易跟比例圖打架，所以定為只用 C。

八、方向由程式算，描述由模型寫2026-11-20

  • 只有一個正確答案的幾何問題（相機朝哪個方位、太陽在畫面的哪一邊），由程式照地圖算，不交給模型在腦中轉方向。
  • 算法：相機格子指向它對準的人（那個時間點站的格子）＝相機朝向；地圖的太陽方位相對朝向 → 正前、左前、左、左後、正後、右後、右、右前（scripts/sun_side.py）。
  • 程式把結果當資料放進第 15 步的背景 request，例如「太陽在相機的正後方（相機朝東拍）」；背景模型照這個方向寫光線的描述（光的顏色、影子往哪倒），方向不能改。
  • 第 15 步檢查要比對：模型寫的光線方向跟程式算的一致，不一致就退回重送。
  • 這跟第一條不衝突：程式只算方向這個事實，背景句子還是模型寫；就像地圖也是程式搬給模型的資料。
  • 2026-11-21 擴大到地標：畫面左側／中間／右側各看得到哪些地形和物件（樹林、建築會擋住後面），也由程式算（scripts/view_side.py），背景只能寫算出來看得到的東西，鏡頭外的地標不准寫。

為什麼：2026-11-20 EP1-new 第一場，01-05、01-05W 相機朝東拍、夕陽在背後，背景卻寫「夕陽從畫面正前方直射」；01-02 朝西北拍，卻寫「夕陽從鏡頭後方」。背景 request 只給了相機格子和「對準 TEEN」，沒給 TEEN 站哪一格，模型算不出相機朝向、只能猜；就算給了，要在腦中旋轉方向也容易轉反。

九、改版另出新版，舊版保留2026-11-25

  • 第 18 步改版時，倒回前面步驟改到的檢查文件（劇本、分場表、分鏡表）另出新版，接續編號 v2、v3……
  • 舊版原封不動留著，放在原網址底下的 v/（例如 breakdown-ep1-new/v1/）；原網址永遠是最新版，首頁、集頁的連結都連到最新版。
  • 沒改到的文件不升版（這一輪劇本沒改，就還是 v1）。
  • 每一輪三份各是第幾版記在 docs/versions.json；三份頁面上方都有版本列，看得到這一輪是「劇本 v1・分場表 v2・分鏡表 v2」，也能點到舊版。
  • 做法：重產頁面前先跑 scripts/snapshot_version.py <集> <這一輪名稱> <為什麼改> <改到的文件代號>，把現在這版存成 v<N>/、記一輪，再重產頁面。

為什麼：2026-11-24 改版（實驗室牆面、甲龍空地）直接在原網址覆蓋分場表和分鏡表，改之前長什麼樣子看不到，只能從 git 救回來。
