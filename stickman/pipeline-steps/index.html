13. 補背景和參考圖 🧪

改 11-12 改成 LLM 手寫，程式拼的背景停用

誰：背景由 LLM 手寫，你核對。　給你用：分鏡表（每格地圖下面的「中文 prompt」）　我用：背景：docs/requests/EP1-NN_bg_hand.json；參考圖：add_background.py

規定（2026-11-12 使用者定）：

  • 任何跟 prompt 有關的都不可以用程式：背景描述、每格附哪些參考圖、prompt 文字，都由 LLM 逐格看地圖決定；程式只負責搬運（貼進 Flow、下載、切圖）。可以用程式組 request 去問模型，但無論如何一定要是模型決定。
  • 景的描述由 LLM 負責，不可以用程式拼。LLM 一格一格看地圖（相機位置、視野），用直白的句子寫，像在描述一張照片。
  • 寫法：先講鏡頭對著哪面牆或哪個方向，再講那邊有什麼；東西用彼此的關係定位（窗下的書桌、書桌前的椅子、靠左牆的床）；最後講不在畫面裡的門窗和光線。
  • 不寫東南西北（Flow 沒有地圖）、不寫幾公尺（Flow 不會量距離）、不用「前景／中景／背景」「畫面最後面」這種分層詞。
  • 範本：EP1-02-01。中文給你核對，英文接在 prompt 後面。

參考圖：由 LLM 逐格決定（11-12 改，原本由程式依入鏡角色和關鍵字選，已停用）：入鏡角色的設定圖、HERO 和恐龍同框時的比例圖 PAIR2、畫面裡看得到的牆面圖（房間 ROOM_*_WALL、實驗室 LAB_*_WALL：正對一面牆附 1 張、對著角落附 2 張、鏡頭背後不附）、畫面有道具就附 REF_PROPS。舊做法：順序：入鏡角色的設定圖 → HERO 和恐龍同框時那隻恐龍的比例圖 PAIR2 → 地點設定圖（實驗室 → REF_LAB、HERO 房間 → REF_ROOM）→ 畫面有手機、相機、電擊槍、回家按鈕、生存指南就附 REF_PROPS。只附 Flow 專案裡有的。

為什麼不用程式：map_background.py 用射線算出看到什麼再拼句子，寫出「背後是西牆」「離相機約 4 公尺」「背景橫跨整個畫面：書桌」，Flow 看不懂、使用者也看不懂；02-08 因此把窗戶畫到 HERO 背後。程式最多拿來對照哪些東西在視野裡，句子不能用。

為什麼要補背景：分鏡設計的模型拿到地圖也常把背景寫反（第 7 幕 10 格把河寫成 "forest behind"）；補上背景後 Flow 會照著畫。

14. Flow 畫圖 🧪

誰：我操作。　我用：flowbot/scene_draw.py

怎麼做：一幕一幕畫：附參考圖、貼 prompt、送出，一次出 4 張，已畫好的格子跳過。

16. 補救 ✅

誰：我提，你定。

先後順序（2026-11-13 定）：

  • 優先處理要改 prompt 的：prompt 沒寫對、沒寫到，或寫了會畫錯的（例：沒寫 HERO 站在圓環裡、直接寫甲龍害偽裝破功、沒寫手要純白、背景寫錯）。
  • 多畫幾張就能解決的先不處理：prompt 已經寫對、只是 Flow 剛好畫歪一兩張（例：一張畫成光頭、一張細手細腳）。這種直接在分鏡表標「不要這張」，挑別張。
  • 判斷方法：先打開那格的 prompt 看有沒有寫到。有寫到＝多畫幾張；沒寫到或寫錯＝改 prompt。
  • 改 prompt 的格在分鏡表用「表達不好，要重寫 prompt」給意見；舊版存進修改紀錄（scripts/revisions.py），可以還原。

規則：

  • 大小不對只用兩種補救：恐龍只露一部分，或鏡頭拉遠。不用 Flow 的修改功能。
  • 失敗就整段 prompt 重寫，不疊補丁句；每一格都重畫，舊圖只當構圖參考。
  • 測試先講要回答什麼，對照只差一個條件。
